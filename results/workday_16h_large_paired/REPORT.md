# Budapest shared GA comparison for cases 074, 075 and 099

The penalty improvement reproduced at both 224 and 225 addresses. Across
seeds 0, 1 and 2, relocate-only reduced the penalty in all nine pairs.
The reductions were EUR 118,000 on case 074, EUR 130,000 on case 075 and
EUR 16,000 on case 099. All 18 final schedules passed revalidation.

| Case | Addresses | GA arm | Operating cost (EUR) | Soft penalty (EUR) | Total objective (EUR) | Longest vehicle (min) |

| 074 | 224 | Relocate only | 1,574.9274 | 128,000 | 129,574.9274 | 956.04 |
| 075 | 225 | Original | 1,733.0125 | 260,000 | 261,733.0125 | 941.97 |

| 099 | 249 | Original | 1,856.1111 | 250,000 | 251,856.1111 | 958.78 |
| 099 | 249 | Relocate only | 1,856.7389 | 234,000 | 235,856.7389 | 959.71 |

All three seeds produced identical final metrics within each case and arm.
Relocate lowered the total objective by EUR 118,118.0668, EUR 130,042.1162
and EUR 15,999.3722, respectively. On case 099, operating cost increased by
EUR 0.6278 while the penalty dropped by EUR 16,000. The longest vehicle day
increased in all three cases and stayed within 960 minutes.

Each case used one validated initial schedule for both arms and all seeds,
population 32, a 200-generation limit and a cap of 6,032 combined counts.
Swap was disabled. Each original run used 6,032 GA evaluations and zero
local trials. Each relocate-only run used 2,612 GA evaluations and 3,420
local trials. These units have different computational costs. This result
describes the three selected cases under the stated budget and warm start.

The three original seed-0 checkpoints were reused after verifying the
instance hash, initial plan hash and routes, solver hash, Python version and
run settings. The other 15 runs were executed on the current solver.
Earlier case 099 pilot files lack a solver fingerprint. Runtimes in
`summary.csv` include the environment of the original run when reused.

The original per-run JSON records and generated initial-plan copies are
retained locally and are not included in this PR. Checkpoint paths in the
summary and the top-level trace CSV identify the original audit sources;
they are provenance text, not links to records supplied by this PR.

From the repository root, use a new output directory:

```powershell
python run_workday_large_paired.py --instances generated/shared_workday_16h_pilot_local --output results/workday_16h_large_paired_repro --jobs 8
```

Generate the instances first using the commands in the
[benchmark report](../../WORKDAY_16H_BENCHMARK.md#reproduction-commands).
The runner executes the solver runs and writes `summary.csv`, configuration,
reuse decisions, initial-plan copies and run checkpoints. Missing reusable
checkpoints trigger solver runs. The `paired_deltas.csv` and this report
are supplied with the PR but are not automatically generated by this command.
